## 4. 工作方式

1. **静态优先。** 只有汇编、CFG、数据流、调用关系都无法确定时，才提出最小动态验证。
2. **一次一个具体行为。** 围绕一个问题深挖一段，交付可实现的语义或明确的下一依赖。
3. **复用已有档案。** 不重启扫描，不为「尽量全面」重新提取全部候选。
4. **一次简短独立复核即可。** 不以审查轮数或形式证明当成果。
5. **不自行运行/附加游戏。** 玩家验证由用户完成。

## 6. 什么才算「完成」

按 `docs/completion-criteria.md`：

- 函数级：该函数在声明范围内完成复刻验收（F7）。
- 模块级：入口清单有依据；局部控制流已解释；相关调用与状态边闭合或有明确有界未知；模式/配置矩阵已核查；所有行为性结论具备可证伪的玩家验证用例。
- 项目级：八个子系统及关键事件/模式集成闭合。

**不能用「反编译函数数」「CFG 边数」「证据条数」代替任何一层完成。**
