# 首次运行与验收

装好之后按顺序做完这几步。**每一步都有明确的通过标准**，做不到就不要往下走。

目标：在 10 分钟内确认「插件真的在工作」，并且知道哪些功能还不能信。

## 0. 准备

- 一张熟悉的 Tank Run 地图，例如 `c2m1_highway`。
- 至少一名真人玩家（你自己）。
- 管理员权限（`sm_tank_status` 需要一般管理员，菜单写入需要配置管理员）。
- 一份干净的 `logs/tankrun_control.log`（删掉旧的或记下当前行数）。

## 1. 加载与版本

服务器控制台：

```
sm plugins list
```

**通过**：出现 `Tank Run Control Center 2.2.11`。
**不通过**：版本号不是 2.2.11 → 装错文件；插件根本不出现 → 看 [故障排查](../operations/troubleshooting.md)。

## 2. 依赖状态

```
sm_tank_status
```

**通过**，输出里应包含（实际措辞以你服务器为准，关键字段位置固定）：

```
Tank Run 综合控制中心 v2.2.11 | 功能开关：开启
模式：tankrun | 地图：... | 难度：... | tick 间隔 0.0100 秒（100 tick）
依赖：Left4DHooks=可用 | SDKHooks=可用 | Tank Run 脚本=已连接 Tank Run 模式脚本
Tank：AI 0 只 / 玩家 0 只 | 自动生成：开（间隔 2 秒，上限 30）
统一生成：在场 0/30（补位 0，开关开）| 真人离开安全区：否 | 阶段：暂停
刷点难度：普通遮挡（跟随游戏难度）
客户端槽位：1/18 | 剩余 17 | 交接保留 0 | 当前原版 Tank 上限 17
首石优先：开 | 武器入口禁拳：已加载 | 投石瞄准：原版
```

逐项看：

- `tick 间隔` 应为 `0.0100` 秒（100 tick）。不是 100 tick 时先记下来，后续所有时序结论对你都不适用。
- `Tank Run 脚本=` 应为「已连接 Tank Run 模式脚本」。其它取值含义：
  - `当前模式不是 tankrun` → 模式不对。
  - `模式脚本未提供 SessionState/SessionOptions` → 没加载官方 Tank Run 脚本。
  - `地图/实体系统未就绪，脚本探测已推迟` → 等地图加载完再查一次。
  - `脚本桥无返回值` / `脚本执行失败` → 看日志，通常是有别的插件也要写同一批字段。
- `武器入口禁拳：已加载` 表示 DHooks 签名匹配上了。显示「未加载」时首石仍有输入拦截路径，但第一道防线不存在。
- `阶段：暂停` 在玩家离开安全区前是正常的。

**通过标准**：插件自己在日志里也写了加载行。检查 `logs/tankrun_control.log` 第一行是 `插件已加载 v2.2.11`。

## 3. 菜单

游戏内以管理员身份输入：

```
!tank
```

**通过**：
- 菜单标题是「Tank Run 综合控制中心」。
- 能看到 11 个编号分节（1. Tank 生成与数量管理 … 11. 插件状态、兼容性与帮助）。
- 随便进一个分节，再按「返回上一级」能回来。
- 分节里的参数行显示**当前实际值**，不是空白。

## 4. 一次手动生成（最关键的一步）

同一张图，玩家离开起始安全区后：

```
sm_tank_spawn native
```

**通过**：聊天栏/控制台报告生成结果，且

1. `sm_tank_status` 里 `Tank：AI 1 只`；
2. 菜单「8. 当前 Tank 列表与独立控制」里出现这只 Tank；
3. 日志出现对应的生成记录。

**不通过**的常见原因按顺序排查：
- 玩家还在安全区 → 插件按设计不生成。
- 脚本阶段未开放（`TanksDisabled` 或数量门为 0）。
- 客户端槽位已满 → 看 `sm_tank_status` 的槽位行。
- 选位失败 → 日志会写具体原因。

## 5. 参数写入与读回

```
sm_tank_set tankrun_auto_interval 5
sm_tank_params
```

**通过**：`sm_tank_params` 里 `tankrun_auto_interval` 显示 `5`，并且命令回显「已写入，实际读回 …」。

再恢复：

```
sm_tank_restore tankrun_auto_interval
```

**通过**：读回恢复成注册默认值 `2.0`。

> 这一步验证的是「参数层能写能读」，**不是**验证这个参数在游戏里产生了什么效果。效果验证见第 7 步与 [验收剧本](../user-guide/validation-playbook.md)。

## 6. 诊断导出

```
sm_tank_dump
```

**通过**：生成 `addons/sourcemod/logs/tankrun_control_dump.txt`，里面有版本、模式、依赖、Tank 数量、参数当前值/原始值。

这份文件是后续所有问题排查的输入，出问题时先留一份。

## 7. 一项行为验证（选一个做）

不要一次全测。按你当前关心的问题选一条：

| 你关心什么 | 做什么 | 看什么 |
|---|---|---|
| 刷点位置 | 切「Tank Run 刷点难度」= 1（遮挡），在开阔路段生成 | Tank 是否从墙后出现，而不是凭空出现在视野里 |
| 满员轮换 | 把 `tankrun_auto_limit` 临时设 2，两只都留活 | 下一次生成时最早那只死亡，新的一只出生 |
| 首石 | 生成一只 Tank 并走进它视野 | 日志里同一只 Tank 的「首石请求 → 激活 → 离手」序列 |

**注意**：这三项的完整判定都需要日志 + 画面，单看画面容易误判。判定方法见 [验收剧本](../user-guide/validation-playbook.md)。

## 8. 恢复

测完把改过的参数写回测试前的读数：

```
sm_tank_restore all
```

或菜单「9. 参数预设与配置保存」→「恢复全部参数初始值」。

⚠ `sm_tank_restore all` 会把**所有**参数恢复到插件记录的初始值，包括你之前有意调过的。恢复前先 `sm_tank_params` 留一份读数。

## 通过之后

- 想知道每个菜单项和参数具体做什么：[v2.2.11 用户指南](../user-guide/control-center.md)

- 遇到异常：[故障排查](../operations/troubleshooting.md)

## 尚未验证的部分（不要当成已可用）

即使上面 8 步全部通过，以下功能在游戏内**仍未验证**，只做过编译与静态检查：

- 遮挡刷点在真实地图上的实际分布。
- 满员轮换在客户端槽位耗尽时的失败路径。
- 首石在自然攀爬、高台边缘、贴脸场景的成功率。
- 高容量配置下 22 只原版 + 8 只补位同时存在的稳定性。
- 八名真实 Steam 客户端同时连接的容量表现。
- 128 tick 下的任何行为。

依据：`docs/tankrun-control-center.md` 各版本末尾的「待验证」说明，以及 `indexes/status.json`。
