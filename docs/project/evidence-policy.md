# 证据政策（操作细则）

面向要改这个仓库的人。规则的目的只有一个：**让下一个人能判断一条结论该不该信**。

概念定义见 [研究方法](../research/method.md)。本文是执行层面的「怎么做」。

## 1. 每个地址/偏移必须带构建身份

任何写到地址、偏移、字段布局的地方，必须能追到 `server.dll` 的 SHA256。

| 场合 | 要求 |
|---|---|
| 报告正文 | 首次出现时写明 SHA256 + 基址 |
| 索引 JSON | 带 `artifact_sha256` 字段 |
| gamedata | 注释里写 SHA256 与 VA |
| 文档引用地址 | 同时给出「哪个构建」 |

**新哈希 = 新构建。** 不要拿旧地址往新 DLL 上套。

## 2. 原始证据只增不改

| 目录 | 规则 |
|---|---|
| `evidence/` | 只增。不改写、不重命名、不删除 |
| `analysis/*/`（已交付轮次） | 只增。修正写在新的补充文件里 |
| `history/` | 冻结 |
| `build/releases/` | 已发布的包不覆盖；新版本新建目录 |

需要更正旧结论时：**新开一节或在同目录加 `*-followup.md`**，不要改历史正文。历史限制被改写会让「当时的证据边界」消失。

## 3. 四种事实不互相升级

| 类型 | 判据 | 不能做什么 |
|---|---|---|
| 观察到的字节/指令 | 可直接复现的读取 | 不能说成「运行行为」 |
| 推导结论 | 有明确前提 | 不能省略前提 |
| 接口旁证 | 公开源码/头文件 | 不能当成原生分支证据 |
| 玩家验证 | 有记录的场景与输入 | 不能外推到全部情形 |

**反例**：RTTI 里出现某个类名 → 不等于该类的实例走了这条调用。虚表里有某个槽 → 不等于运行时接收者就是这个类型。

## 4. 分支必须成对登记

| 结构 | 必须登记 |
|---|---|
| 条件跳转 | 两个后继 |
| switch | 每个 case + default |
| 循环 | 入口、退出、回边 |
| 间接调用 | 标为未解析，计入前沿 |

**不要**因为一条分支「看起来不会走到」就省略它。省略等于隐藏未知。

## 5. 未观察不等于不存在

- 「没找到生产者」→ 写「未找到」，不写「没有」。
- 「解析失败的间接调用」→ 计入开放前沿，不算已闭合。
- 「某函数没被引用」→ 要说明是「在本次证据集合内没被引用」。

## 6. 三种值分开记录

| 值 | 来源 | 误用后果 |
|---|---|---|
| 注册默认 | ConVar 注册字符串 | 被当成运行值 |
| 模式声明 | 模式脚本/配置的覆盖 | 被当成生效值 |
| 实际读回 | 运行时 `GetFloat`/`GetInt` | —— |

文档里写「默认 X」时必须说清是哪一种。

## 7. 运行时验证的门槛

要写 `RUNTIME_VALIDATED`，必须同时具备：

1. 构建身份（短哈希）
2. 场景（地图、模式、难度、人数、tickrate）
3. 输入（参数值、操作序列）
4. 观测记录（日志行/时间/截图）
5. 对照（开/关同条件）

缺任何一条 → 只能写「有运行时观测，条件不足」。

## 8. 命名

- 从 RTTI / 调用上下文推断的名字**不是原始符号**。首次出现时标注「分析者命名」。
- 恢复不出名字时直接用地址或整数枚举，不要编造语义名。
- 中性名优于错误名。

## 9. 复核

一次简短独立复核，只查三件事（`docs/review-workflow.md`）：

1. 结论是否被所引证据/VA/指令支持？有没有误读 ABI/this/浮点/对象类型？
2. 是否混淆目标、Body、移动、武器、出生 NAV？是否把局部顺序说成全局规则？
3. 有没有会改变实现的遗漏条件、失败/中断后继、关键未闭合依赖？

输出「可继续」或具体修正点。**不以审查轮数当成果。**

## 10. 提交前自检清单

- [ ] 新增地址都带 SHA256
- [ ] 新增结论都带等级标记
- [ ] 新增分支都登记了两个后继
- [ ] 没有把默认值写成运行值
- [ ] 没有把推断写成 `CONFIRMED`
- [ ] 没有改动既有证据与历史报告正文
- [ ] `indexes/status.json` 与相关模块报告已更新
- [ ] 新文档里的相对链接可解析
