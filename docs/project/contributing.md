# 贡献指南

## 先读

1. [证据政策](evidence-policy.md) —— 不接受违反它的 PR
2. [研究方法](../research/method.md) —— 你要用的标记
3. [测试](testing.md) —— 四层，各自能声明什么

## 你可以贡献什么

| 类型 | 门槛 |
|---|---|
| 文档修正（错别字、死链、版本号） | 低。直接提 |
| 新增玩家验证样本（按验收剧本格式） | 中。必须带构建、场景、输入、日志行号 |
| 修复已确认的静态错误 | 中。必须指到具体指令 |
| 新功能 | 高。必须先有公开接口证据 + 实现 + 编译 + 一条实服日志 |
| 新研究报告 | 看证据政策 |

**不要**提交：

- 没有构建绑定的地址；
- 把推断写成 `CONFIRMED` 的结论；
- 修改既有证据或历史报告正文（用 follow-up 文件）；
- 未经确认的「优化」；
- `.smx` 产物（`.gitignore` 已忽略）。

## 提交格式

### 文档类

```
docs: <改了什么>

- 修正 <文件>:<行> 的 <问题>
- 依据 <来源>
```

### 研究类

```
research: <轮次名>

- 新增 <函数/边> 的 <结论>（D/I/API/R/U）
- 未闭合：<具体项>
- 更新 indexes/status.json 与 <模块报告>
```

### 代码类

```
feat/fix: <一句话>

- 改动：<文件:行>
- 依据接口：<native/forward/ConVar>
- 编译：SourcePawn <版本>，0 error 0 warning
- 验证：<第几层>，记录见 <文件>
```

## 代码约定

- SourcePawn 1.12，`#pragma newdecls required`。
- 只用公开接口。原生地址只允许出现在 gamedata 与 `tr_rock.inc` 的 detour 安装处。
- 任何写入都会读回校验，失败必须写日志并回报实际值。
- 新增参数要同时更新：`TR_CreateConVar`、`TR_RegisterParams`、文档的参数表、`TR_PARAM_MAX`（如果满了）。
- 只对 AI Tank 生效的策略，必须检查 `TR_IsAiTank`。
- 每个新 forward 处理都要在 `TR_FeatureEnabled()` 关闭时立即返回。

## 文档约定

- 中文为主，标识符与代码用英文。
- 每个断言尽量给出处（源码行号或报告文件）。
- 区分「已验证 / 已有观测 / 未验证 / 推测」。
- 相对链接以仓库根为基准写；本机绝对路径不要写进新文档。

## 兼容性

| 变更 | 是否破坏兼容 |
|---|---|
| 新增 `tankrun_*` 参数 | 否 |
| 改参数默认值 | **是**（服务器配置可能依赖旧默认） |
| 删除参数 | **是** |
| 改命令参数 | **是** |
| 改日志字段 | 可能（外部解析器会坏） |
| 改 gamedata 签名 | 是（同时要更新 SHA256 注释） |

破坏性变更必须：升 minor/major、在 [版本表](../reference/versions.md) 写明、在升级文档里给回滚路径。
