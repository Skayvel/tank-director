# 预设与设置持久化

控制中心有三层「值」和两个持久化文件。分清它们能避免「我恢复了怎么没变」这类困惑。

## 1. 三层值

| 层 | 来源 | 何时变 |
|---|---|---|
| **注册默认值** | ConVar 注册时写死的字符串 | 不会变（除非换版本） |
| **原始值** | 插件首次修改某参数**之前**读到的值 | 首次修改时记录一次 |
| **当前值** | 引擎/插件此刻的真实值 | 任何写入 |

菜单参数页同时显示前两者；`sm_tank_params` 显示当前值；`sm_tank_dump` 显示全部三层。

## 2. 恢复初始值恢复的是哪一层

`sm_tank_restore <参数>` / `sm_tank_restore all` 恢复到**原始值层**（`configs/tankrun_control_originals.cfg`）。

- 如果某参数从未被本插件改过，就没有原始值记录，`restore` 对它无效。
- `restore` 不会清空原始值文件，因此可以反复执行。
- **脚本参数**（`tankrun_script_*`）不在恢复范围内，要单独 `sm_tank_set` 或换图让脚本重建。

菜单里的「设为引擎注册默认值」是另一个动作：直接把参数设成注册默认值，不经过原始值层。

## 3. 预设（8 个槽）

```
sm_tank_preset list
sm_tank_preset save 3 名字
sm_tank_preset load 3
sm_tank_preset delete 3
```

对应文件 `configs/tankrun_control_preset1.cfg` … `preset8.cfg`。

### 预设里有什么

**只有 `TRK_PLUGIN` 类参数**（插件自己的 29 个 `tankrun_*`）。引擎参数（`tank_*`、`z_*`、`nb_*`）与脚本参数（`tankrun_script_*`）**不写入预设**。

原因：引擎参数可能被模式或其他插件覆盖，脚本参数的权威来源是脚本本身；把它们写进预设会造成「以为保存了、其实恢复不了」。

### 应用预设时

- 逐项校验范围，越界项跳过。
- 报告 `槽位 N 应用完成，成功 M 项`；`M` 小于槽内项数说明有项被跳过。
- 槽位为空或读取失败 → `槽位 N 为空或读取失败`。

## 4. 设置文件

`sm_tank_preset` 之外，还有一份「当前插件设置」：

| 动作 | 命令 | 文件 |
|---|---|---|
| 保存 | 菜单「保存当前插件设置到文件」 | `configs/tankrun_control_settings.cfg` |
| 加载 | 菜单「手动加载插件设置文件」/ `sm_tank_reload` | 同上 |

与预设的区别：

- 预设是 8 个具名快照，手动应用；
- 设置文件是**单一全局配置**，插件在换图、回合开始、重载后会重新应用它。

## 5. 自动保留（v2.1.0+）

菜单、`sm_tank_set`、手动预设写入的参数值会**自动保留到本次服务端进程结束**：

- 换图、回合开始、重载插件 → 重新应用。
- 玩家离开 → **不**触发清空。
- 原版脚本在同一回合阶段切换时改写字段 → 插件的保留设定仍会重新应用。

**进程重启后不保留。** 完整重启后，初始值来自引擎、模式与服务器启动配置。

需要跨重启保留时，用「保存当前插件设置到文件」或预设。

## 6. 冲突处理

`tankrun_conflict_mode`：

| 值 | 行为 |
|---|---|
| `0`（默认） | 发现外部修改时，**警告后写入** |
| `1` | 发现外部修改时，**拒绝写入**，保持外部值 |

判定方式：写入前比较「本插件上次写入的值」与当前实际值。不一致就认为有外部修改。

日志会记录冲突次数，`sm_tank_status` 的「冲突 N 次」也会累加。

**这与 `sm_cvar` 的关系**：用 `sm_cvar` 直接改一个 `tankrun_*` 参数，插件会把它当成外部修改。这不算错，但会让插件的「上次写入值」失效，后续菜单写入可能触发一次冲突警告。

## 7. 换图 / 回合 / 重载的行为

| 事件 | 插件做什么 |
|---|---|
| 地图切换（`OnMapStart`） | 复位运行状态、停旧定时器、确保扫描/自动生成定时器、排队探测 |
| 回合开始（`round_start`） | 复位回合级状态（首石窗口、待判定投石） |
| 回合结束（`round_end` / `mission_lost` / `map_transition` / `finale_vehicle_leaving`） | 清理首石窗口与待判定投石 |
| 插件重载 | 重新读设置与原始值、重新探测依赖；**已在场 Tank 的出生顺序丢失** |
| 服务器重启 | 全部回到引擎/模式/启动配置 |

## 8. 常见困惑

**「我 `restore all` 了，参数还是我设的值」**
→ 该参数没有原始值记录（从未被插件改过），或它是脚本参数。

**「我保存了预设，换图后没了」**
→ 预设不会自动应用。换图后应用的是设置文件，不是预设。要手动 `sm_tank_preset load N`。

**「我 `sm_cvar` 改了引擎参数，菜单显示变回来了」**
→ 插件在换图/重载后会重新应用保留值。要让它长期生效，写进服务器启动配置并在插件里设为同一值。

**「删掉 originals.cfg 会怎样」**
→ 失去恢复能力。当前进程内仍可写入，但 `restore` 找不到原值。

**「预设槽 3 应用只成功了 20 项」**
→ 槽里保存时是 29 项，其中 9 项在当前构建不可用（引擎 ConVar 未注册或脚本未连接），被跳过。
