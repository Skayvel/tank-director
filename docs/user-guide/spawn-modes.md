# 生成方式与选位

控制中心接管生成后，一只 Tank 出现在哪里、什么时候出现，由下面几层共同决定。理解这几层能避免把「没刷出来」误判成插件坏了。

## 1. 三层门槛

```
① 模式阶段门 ──→ ② 真人离开安全区 ──→ ③ 调度到期 ──→ 选位 ──→ 提交创建
```

| 层 | 判定 | 不满足时 |
|---|---|---|
| ① 模式阶段门 | 原版脚本 `SessionState.TanksDisabled` 为假，且 `cm_TankLimit > 0` | 状态显示「阶段：暂停」，不生成 |
| ② 真人离开安全区 | 至少一名存活真人确实离开起始安全区（结合 Director、起始检查点与脚本 `instartarea`） | 状态显示「真人离开安全区：否」，不生成 |
| ③ 调度到期 | 距上次尝试 ≥ `tankrun_auto_interval`，且未达 `tankrun_auto_limit` / 有效槽位上限 | 等待 |

只有三层都通过，才会进入选位。

## 2. 五种生成方式

`tankrun_spawn_mode` 或 `sm_tank_spawn <方式>` 选择：

| 值 | 名称 | 选位来源 | 适用 |
|---|---|---|---|
| `0` | 原生随机区域 | 引擎 NAV 随机区域（`L4D_GetRandomPZSpawnPosition`） | 最接近原版行为 |
| `1` | 距离带 | 多次取原生候选，按最小/最大距离与空间检查筛选 | 想控制与玩家的距离 |
| `2` | 准星位置 | 视线前方 150 单位、向下 400 单位找地面，做 hull 与地面法线检查 | 定点复现、摆拍、测试 |
| `3` | 脚本 ZSpawn | 原版 `ZSpawn`（`type=8`） | 想完全走原版脚本路径 |
| `4` | 幸存者附近原生选位 | 以某名幸存者为锚点的原生选位 | 想让 Tank 出现在某人附近 |

### 诚实边界

- `1` 和 `2` 是**插件策略**，不是原版生成算法的复刻。
- 原版的最终选位仍由引擎 NAV 决定；插件只是决定「向引擎要哪个候选」和「接受哪一个」。
- `tankrun_spawn_fallback = 1` 时，距离带/准星失败会回退到原生随机区域。

## 3. 统一前沿选位（v2.2.0+）

v2.2.0 起默认路径不再是上面五种里的单一一种，而是统一的**领先玩家前沿选位**：

1. 找当前进度最靠前的存活真人。
2. 在其前方 220–3000 单位范围内找候选点。
3. 候选来源混合：原生随机点、随机半径与角度的地面投影、地图导航点（导航中心按图缓存）。
4. 逐个候选做检查（见第 4 节）。
5. 通过则提交创建。

手动生成、自动单只、自动双只、满员补位、内嵌补位 **共用同一套选位**。

## 4. 距离段随机（v2.2.6+）

`[tankrun_spawn_min_dist, tankrun_spawn_max_dist]` 被**均分为三段**：

| 段 | 默认范围（220–3000） |
|---|---|
| 近 | 220 – 1147 |
| 中 | 1147 – 2073 |
| 远 | 2073 – 3000 |

每次生成随机排定三段的查找顺序，从**第一个有合格候选**的段内随机选点。同段内优先使用进度更靠前的点。

效果：连续生成不会总是贴着最近距离，也不会总是最远。日志会写出实际距离与所处段。

## 5. 候选合格条件

所有条件都满足才接受：

| 条件 | 说明 |
|---|---|
| 所有存活生还者的最小距离 | 到**每一名**存活生还者都 ≥ `tankrun_spawn_min_dist` |
| 领先真人的最远距离 | 到领先者 ≤ `tankrun_spawn_max_dist` |
| 前线进度 | 候选点流程进度不低于领先者（可回追） |
| NAV 可达性 | `L4D2_NavAreaBuildPath` 从候选区域到目标区域可行 |
| 安全区限制 | 不能在起始安全区内 |
| 出生空间 | Tank hull 在候选点可容纳 |
| （遮挡档）全队视线 | 见第 6 节 |

三段都没有合格候选 → 等下一次调度，不强行生成。

## 6. 刷点难度（v2.2.8）

`tankrun_spawn_visibility`：

| 值 | 名称 | 规则 |
|---|---|---|
| `0` | 跟随游戏难度 | 简单/普通 → 遮挡；高级/专家 → 前线 |
| `1` | 普通遮挡 | 所有难度都要求遮挡 |
| `2` | 高难度前线 | 所有难度都用 v2.2.7 的前线选位（允许在视野内出现） |

### 遮挡判定怎么做

对同一批候选，从**每一名存活生还者的眼睛**出发，检查 Tank 出生包围盒的采样点：头、躯干、脚部、两侧。

- 任一个采样点可见 → 跳过该位置。
- 队友模型与玩家朝向**不计入**遮挡。
- 使用 `MASK_VISIBLE` 射线。

效果是「Tank 可以从墙后出生后立刻走进视野」，但不会在你眼前凭空出现。

**这一条只通过了编译与遮挡算例，真实地图上的分布尚未由玩家验证。**

## 7. 满员轮换

达到上限时：

1. 先找位置（`tankrun_spawn_visibility` 规则同样适用）。
2. 找到后才处死**最早出生**的 AI Tank。
3. 确认槽位释放（死亡 Bot 仍可能占槽）。
4. 在该帧重新复核选点（遮挡档会再查一次视线）。
5. 补一只。

- `tankrun_rotate_oldest = 0` 时达到上限就停住，不轮换。
- 手动生成不受轮换开关影响。
- 临时失败每 0.10 游戏秒重试，单次补位最多等待 2 游戏秒。
- 一个待补位请求只处死一只 Tank。

## 8. 生成失败怎么读日志

| 现象 | 常见原因 | 查什么 |
|---|---|---|
| 完全不尝试 | 阶段暂停 / 真人未出安全区 / 自动生成关闭 | `sm_tank_status` 的「阶段」「真人离开安全区」「统一生成」行 |
| 尝试但失败 | 三段都无合格候选 | 日志的选位失败原因；确认距离范围是否过窄（如 min 800 / max 900） |
| 前端成功但没实体 | 槽位耗尽 | `sm_tank_status` 的「客户端槽位」行；`剩余` 是否为 0 |
| 刷出来又被换掉 | 轮换触发 | 日志的「满员轮换」行，含被处死的 userid |

## 9. 调参建议

| 目标 | 建议 |
|---|---|
| 想更接近原版 | `tankrun_spawn_visibility 0` + 专家难度（走前线）；或直接用 `sm_tank_spawn native` |
| 想避免「凭空出现」 | `tankrun_spawn_visibility 1`，并把 `tankrun_spawn_min_dist` 提到 400 以上 |
| 想在开阔图也有变化 | 保持默认 220–3000 三段随机 |
| 狭窄地图总是不刷 | 缩小 `tankrun_spawn_max_dist`（如 1500），让三段都落在可达区域 |
| 只想测行为，不想等 | `tankrun_spawn_visibility 2` + `sm_tank_spawn near` |

## 10. 未验证的部分

- 遮挡档在真实地图上的实际出生分布。
- 狭窄路线下是否只用到该处可达的距离段。
- 30 只混合在场时选位与轮换的稳定性。
- 地图触发事件（如警报车、终局）与统一调度的相互作用。
